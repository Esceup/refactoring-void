1. Интерфейс не реагировал на действия.
   Все данные компонента хранились в локальных let-переменных. Их изменение не вызывало перерендер.
   Вынес данные в useState. Все изменения теперь проходят через сеттеры и приводят к перерисовке.

2. Состояние изменялось напрямую.
   Добавление шло через push, удаление через splice, количество существующей строки через existing.quantity += quantity. push и splice меняют существующий массив без создания новой ссылки, из-за этого React не делал ре-рендер компонентов.
   Заменил мутации на неизменяемые обновления через map и filter.

3. select и поле количества не сохраняли значение.
   Обработчики onChange присваивали значение локальной переменной, а не обновляли состояние. Контролируемые компоненты не запоминали ввод: селект отщёлкивался назад, кнопка «Добавить» оставалась заблокированной.
   Привязал onChange к сеттерам useState.

4. Проверка уже добавленной услуги шла по ссылке на объект.
   Поиск selectedServices.find(item => item.service === service) работал, только пока услуги берутся из того же константного массива. При другом источнике данных ссылки не совпадут, и вместо увеличения количества появится дублирующая строка.
   Изменил сравнение на проверку по идентификатору: item.service.id === service.id.

5. Итоговая сумма не считалась.
   totalPrice вычислялся в цикле по локальному массиву, который на каждом рендере создаётся пустым, поэтому итог всегда был равен нулю.
   Убрал цикл и сделал расчёт суммы из актуального состояния через reduce.

6. Количество в input не валидировалось.
   Атрибуты min и max у поля не препятствуют вводу нуля или пустого значения.
   Добавил явную проверку количества на диапазон 1–10 перед добавлением и вывод сообщения об ошибке вместо блокирующего alert.

7. Что добавил поверх исправлений, для удобства.
   Кнопки «+» и «−» в колонке «Кол-во» позволяют менять количество уже добавленной услуги без удаления и повторного добавления строки. Ошибка валидации теперь сбрасывается автоматически при изменении выбора в селекте или инпуте.
